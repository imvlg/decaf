# Запуск спільної мапи de caf

Ця інструкція підключає приватні дані друзів до Supabase, а сторінку сайту залишає на GitHub Pages. Посилання без параметра `?invite=...` працює у локальному режимі: спільні дані не завантажуються й не зберігаються на сервері.

## Що вже налаштовано в коді

У `supabase-config.js` уже записані Project URL і publishable key, які ти надала. Publishable key призначений для браузера. **Не додавай `service_role` key** до сайту або репозиторію: він обходить правила доступу.

## Крок 1. Перевір проєкт Supabase

1. Відкрий [Supabase Dashboard](https://supabase.com/dashboard) і вибери проєкт з адресою `ogfbmschwofnzjweqxhl.supabase.co`.
2. Переконайся, що проєкт запущений, а не на паузі.
3. Відкрий Authentication → Sign In / Providers і ввімкни **Anonymous Sign-Ins** (іноді цей перемикач підписаний **Allow anonymous sign-ins**). Цей тип входу створює профіль без email і пароля. [Офіційна інструкція Supabase](https://supabase.com/docs/guides/auth/auth-anonymous).

## Крок 2. Створи таблиці й правила доступу

1. У репозиторії відкрий `supabase/schema.sql`.
2. Скопіюй увесь файл.
3. У Supabase Dashboard відкрий **SQL Editor** → **New query**.
4. Встав SQL і натисни **Run**.
5. Переконайся, що внизу з’явилося повідомлення про успішне виконання без червоного повідомлення про помилку.

Скрипт створює таблиці для учасників, кав’ярень і відгуків, приватний bucket для фото, функції для вступу за кодом та видалення кав’ярні. Він вмикає RLS і дає клієнтам лише необхідні права. Правила та права на таблиці працюють разом; дивись [документацію RLS](https://supabase.com/docs/guides/database/postgres/row-level-security).

Якщо SQL зупинився на помилці, не виконуй випадкові частини по одній. Скопіюй текст помилки — за ним можна визначити, що саме треба виправити.

## Крок 3. Згенеруй запрошення

Запрошувальне посилання є ключем входу: кожен, хто має його, може приєднатися до спільної мапи. Не публікуй це посилання у відкритому доступі.

1. У SQL Editor створи новий запит і виконай:

   ```sql
   select encode(extensions.gen_random_bytes(32), 'hex') as invite_code;
   ```

2. Скопіюй значення `invite_code` з результату й збережи його окремо. Не додавай його в GitHub, `supabase-config.js` чи `schema.sql`.
3. У новому запиті заміни `ВСТАВ_КОД_З_ПОПЕРЕДНЬОГО_КРОКУ` на свій код і виконай:

   ```sql
   insert into public.de_caf_invites (code_hash)
   values (
     encode(
       extensions.digest(
         convert_to('ВСТАВ_КОД_З_ПОПЕРЕДНЬОГО_КРОКУ', 'UTF8'),
         'sha256'
       ),
       'hex'
     )
   );
   ```

4. Результат має сказати, що додано один рядок. У таблиці лежить лише хеш коду, не сам код.

Якщо посилання потрапить до сторонніх, вимкни старий код запитом нижче та створи новий за кроками 1–4. Учасникам надішли нове посилання: сторінка перевіряє invite-код під час кожного входу.

Це зупиняє нові входи за старим посиланням. Якщо стороння людина вже приєдналася, відкрий **Table Editor → `de_caf_members`**, знайди її за ніком і видали її рядок. Без цього її анонімний профіль лишиться учасником, навіть після ротації коду.

```sql
update public.de_caf_invites
set active = false
where code_hash = encode(
  extensions.digest(convert_to('ТВІЙ_СТАРИЙ_КОД', 'UTF8'), 'sha256'),
  'hex'
);
```

## Крок 4. Опублікуй сайт через GitHub Pages

1. Перевір, що в репозиторії поруч із `index.html` лежать `de-caf-logo.png`, папка `assets`, `supabase-config.js` і папка `supabase`.
2. Закоміть і запуш зміни до GitHub.
3. На GitHub відкрий репозиторій → **Settings** → **Pages**.
4. У **Build and deployment** вибери **Deploy from a branch**, гілку `main` і папку `/ (root)`, потім натисни **Save**. Якщо Pages уже налаштований, перевір, що він публікує саме гілку з цими файлами.
5. Дочекайся повідомлення про успішну публікацію та відкрий адресу сайту. Вона матиме вигляд `https://USERNAME.github.io/REPOSITORY/`.

Project URL і publishable key уже вписані в `supabase-config.js`; після публікації не треба копіювати їх у SQL або інші файли. Publishable key може бути в коді сайту, захист даних забезпечують правила RLS. Секретний `service_role` key нікому не надсилай.

## Крок 5. Відкрий спільну мапу та запроси друзів

1. Додай до адреси сайту `?invite=` і щойно згенерований код. Наприклад:

   ```text
   https://USERNAME.github.io/REPOSITORY/?invite=ТВІЙ_КОД
   ```

2. На першому вході введи свій нік. Він буде біля твоїх відгуків; у формі відгуку ім’я не питається.
3. Відкрий кнопку відгуків і скористайся кнопкою поширення, щоб скопіювати посилання для друзів.
4. Друзі відкривають те саме посилання й кожен задає свій нік один раз.

Анонімний профіль прив’язаний до браузера. Якщо очистити дані сайту або перейти на інший пристрій, Supabase створить новий профіль; старі відгуки залишаться з попереднім ніком. [Документація Supabase про анонімні профілі](https://supabase.com/docs/guides/auth/auth-anonymous).

## Перевірка, що все працює

1. Відкрий звичайну адресу без `?invite=...`: з’являється карта, але спільна стрічка не підключається.
2. Відкрий адресу з запрошенням в окремому браузері або приватному вікні.
3. Задай нік, додай тестову кав’ярню, відкрий її та збережи тестовий відгук.
4. Відкрий запрошення у другому браузері: нова точка та відгук мають з’явитися там теж.
5. Перевір видалення свого відгуку й довге натискання на зернятко кав’ярні.
6. Після тесту прибери тестовий запис або залиш його, якщо він потрібен.

## Якщо щось не запрацювало

- **«Спільний сервер ще не налаштований»** — перевір, чи Pages вже віддав нову версію `supabase-config.js`, і що URL та publishable key у ньому відповідають вибраному проєкту.
- **Не вдається приєднатися** — перевір Anonymous Sign-Ins, чи виконувався `schema.sql` повністю, та чи invite-код скопійовано без пробілів.
- **«Invalid or disabled invite» у консолі або відмова входу** — створи новий invite-код і додай його hash через крок 3.
- **Фото не відкривається** — переконайся, що весь `schema.sql` виконався; саме він створює bucket `de-caf-photos` і політики доступу.
- **Сторінка показує стару версію** — дочекайся завершення GitHub Pages deployment і перезавантаж сторінку без кешу.

## Дані та приватність

При першому вході сайт показує коротке повідомлення: нік, відгуки й фото зберігаються в Supabase та доступні тим, хто має запрошення. Не використовуйте запрошення як пароль до чогось іншого й не додавайте в відгуки чутливі відомості.
